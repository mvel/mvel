# Initial ArithmeticTests results

Date: 2026-10-05. MVEL3 base: `1aaa255c3421b72a050e3015815e15925b5b3546`.
Original MVEL2 tests: `d7c96a36c692df6a9a027a8416e275253fdfda01`.
JDK 17.0.19, Maven 3.9.16. All expressions evaluate on MVEL3.

121 cases: **67 PASS, 22 FAIL, 32 ERROR, 0 skipped**.
FAIL means an assertion failed; ERROR means evaluation raised an exception.
This snapshot is an investigation starting point, not an approved specification
of intentional MVEL3 differences. MVEL2 runtime results were not collected.

Run a case with:

```bash
mvn -DexcludedGroups= -Dtest=org.mvel3.compat.mvel2.ArithmeticTests#testMath3 test
```

Examples requiring investigation:

- `testMath3`: expected Double 33.333333333333336, actual Integer 33.
- `testMath4` / `testMath7`: same numeric value 19, different Double/Integer types.
- `testMath` / `testMathDec30`: Java compilation errors for multiplication involving
  String/Map values without the casts added in the existing MVEL3 tests.
- `testPowerOf`: expected 25, actual 5. Several `**` cases return incorrect values
  rather than rejecting the syntax. `testMath22b` raises a parse error.
- `testUnsignedShiftLeft`: expected 2, actual -2.
- Blocks with implicit last-expression returns: parse errors in the original
  expressions; no `return`, `var`, or terminators were inserted by the adapter.
- `testIssue321`: Java compilation error in the BigDecimal/numeric comparison.

After removing the MVEL2 dependency, all 121 result categories and all assertion
failure messages matched this snapshot. See README.md for verification details.

Full exception messages, generated evaluator names, and stack traces are in
the Surefire report generated by a run. Generated class names and some message
text can change with test execution order and JVM locale.
